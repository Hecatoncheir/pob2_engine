# План выпуска pob2_engine 0.0.8

После [0.0.7](todo_0.0.7.md) окно общей сборки
уже показывает снимок движка, принимает правку уровня и выводит расчёт.
Цель следующего выпуска — пройти в этом же окне весь сценарий выбора
поддержки. Пользователь находит камень в каталоге, сравнивает показатели
до и после его добавления, подтверждает правку и видит новый расчёт.
Применённая поддержка видна в CLI, MCP и PoB II.

Для этого уже есть каталог и [предпросмотр полной группы](docs/CATALOG.md).
При этом [общая правка группы](internal/build/edit.go) пересоздаёт её камни
и задаёт заново `mainActiveSkill` и `includeInFullDPS`. Добавление одной
поддержки в импортированную сборку требует точечной операции.

## 1. Точечное добавление поддержки в движке

- [x] Добавить в `ApplyBuild` правку, которая дописывает одну включённую
  поддержку в выбранную расчётную группу активного набора умений. Использовать
  тот же способ выбора группы, проверки камня и изменения XML, что и в
  `PreviewSupport`. Сохранить атрибуты группы и существующих камней, их порядок,
  расширения XML и остальные группы и наборы. Проверить, что на одном исходном
  снимке и версии PoB предпросмотр и запись меняют вход расчёта одинаково.
- [x] Подключить эту правку к имеющимся командам CLI и MCP. Принимать точный ID
  камня, уровень и качество. Изменение проводить через общий сервис с
  `expected_revision` и `request_id`. Сбрасывать сохранённый расчёт и
  публиковать одно событие только для новой успешно записанной правки.
  Точный повтор запроса возвращает исходный ответ даже после перезапуска.
- [x] Расширить Protobuf добавлением варианта правки, сохранив номера и
  поведение существующих полей. Обновить Go/Dart-клиенты через генератор,
  описание команд и пример полного сценария.

## 2. Предпросмотр и применение в PoB II

- [x] В окне общей сборки ветки `1.x.x` показывать выбранную расчётную группу
  и её камни из снимка. Искать поддержки через `GetCatalog`, передавать в
  `PreviewSupport` выбранный ID, уровень и качество. Показывать исходные и
  новые показатели, разницу, совместимость и предупреждения PoB. При
  неподдержанном варианте показывать причину. Отмена и предпросмотр оставляют
  XML, ревизию и сохранённый расчёт прежними.
- [x] Разрешать применение совместимого варианта для той ревизии, на которой
  выполнен предпросмотр. При правке другим клиентом, переподключении или
  конфликте запросить новый предпросмотр и явное подтверждение. После записи
  обновить группу через `WatchSession`. Кнопка «Рассчитать» использует
  `CalculateBuild`. Показывать итоговые показатели только для текущей
  ревизии входа. Оставить запись XML явным действием пользователя.

## 3. Приёмка и публикация

  с несколькими наборами и дополнительными атрибутами камней проверить
  точность правки, ответы CLI/MCP/gRPC, отсутствие изменений при предпросмотре,
  конфликт, повтор после потери ответа, сохранность XML и исходного ответа
  после перезапуска. Восстановить базу, созданную бинарником `v0.0.7`, и

  В Windows прошли [процессные проверки CLI, MCP и gRPC](internal/integration/add_support_process_test.go),
  восстановление базы официального `v0.0.7` и процессный тест прежнего Dart-клиента.
- [x] Сравнить предпросмотр и полный расчёт применённого варианта с независимым

  Ice Nova с Concentrated Area и случай с диагностикой несовместимой или
  вытесненной поддержки. Сверить числа, статусы и предупреждения. На PoB
  v0.23.1 CLI и gRPC получили эталонные DPS 7,84 → 10,08, а хеш входа
  применённой правки совпал с хешем предпросмотра.
- [x] Пройти путь в PoB II на Windows x64, Linux x64 и macOS arm64. Добавить

  XML без явного сохранения. В [сквозном прогоне PoB II](https://github.com/Hecatoncheir/pob2_ui/actions/runs/45068983447)

  несовместимая поддержка и устаревание предпросмотра при переподключении

  и PoB в отчёте приёмки. Локально проверены совместимость Protobuf с `v0.0.7`

  ревизию Dart API в `pob2_ui`.
