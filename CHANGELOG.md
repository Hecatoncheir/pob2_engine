# История изменений

Изменения фиксируются по версиям. Для автоматического выпуска заголовок версии должен иметь вид `## [0.0.1] - ГГГГ-ММ-ДД` и соответствовать тегу `v0.0.1`. Предварительные версии, например `0.0.1-alpha.1`, оформляются так же. Новые изменения сначала записываются в раздел «Не выпущено».

## [Не выпущено]

## [0.0.4-rc.1] - 2026-11-22

Кандидат выпуска с каталогом активной установки оригинального PoB.
[План и приёмка](todo_0.0.4.md), [примеры CLI/MCP/gRPC](docs/EXAMPLES-0.0.4.md).

- Поиск по полному каталогу PoB: 966 камней, восемь базовых классов,
  1504 базы предметов и 4544 пассива для закреплённого v0.23.1.
  Ответы содержат источник данных и версию дерева; прежний режим Go сохранён.
- Правки групп принимают камни полного каталога и проверяют уровень и качество.
  Неоднозначные имена требуют точного ID. Пассивы проверяются по активному
  дереву PoB, а экипировка сохраняет исходный текст предмета.
- Предпросмотр поддержек принимает уровень и качество через CLI/MCP/gRPC.
  Несовместимые и вытесненные поддержки, ошибки камней и неподдержанные
  свойства надетых предметов получают явные коды диагностики.
- Каталог читается через существующий процесс LuaJIT и кэшируется после
  успешной загрузки. Отмена прерывает процесс; следующий запрос запускает новый.
- Сохранённые правки восстанавливаются из проверенных исходных снимков
  без повторного поиска по изменившемуся каталогу. Проверены прежние ответы
  и отказ при повреждённых входах; формат журнала остаётся 2.
- Независимые эталоны Ice Nova и Concentrated Area с качеством 20,
  проверки полного каталога, правок, совместимости и перезапуска через
  CLI/MCP/gRPC. Нативная приёмка включает переход настоящей базы v0.0.3.

## [0.0.3] - 2026-11-22

Оригинальные расчёты Path of Building PoE2 на LuaJIT с общими сессиями
Go/CLI/MCP/gRPC. [Кандидат принят на трёх платформах](testdata/releases/0.0.3-rc.2/README.md).
Установка и обновление описаны в [руководстве](docs/RELEASE.md).

- При первом запуске устанавливается PoB v0.23.1 с проверкой размера,
  SHA-256 и запуска LuaJIT. Установленный PoB работает без сети.
- `update` и `doctor` в CLI/MCP/gRPC обновляют и диагностируют движок и PoB.
  Замена работающего бинарника сохраняет прежнюю версию при сбое проверки.
- Сессии v0.0.2 сохраняют исходные ответы запросов Go; новые расчёты LuaJIT
  и оба результата доступны после перезапуска.
- Расчёт и предпросмотр сохраняют предупреждения камней и неподдержанные
  пользовательские модификаторы. Поиск и отдельные правки пока используют
  ограниченный встроенный каталог Go; Flutter не подключён.
- Выпуск содержит три самостоятельных бинарника для Windows x64,
  Linux x64 и macOS arm64 и `SHA256SUMS`. Лицензии доступны через `doctor --licenses`.
- Нативные сценарии до и после публикации проверяют чистый кэш,
  параллельную установку, работу офлайн, три умения, CLI/MCP/gRPC,
  восстановление базы и измеряют повторные расчёты Go/LuaJIT.

## [0.0.3-rc.1] - 2026-11-22

Кандидат выпуска с оригинальными расчётами Path of Building PoE2 на LuaJIT.
План приёмки и границы выпуска описаны в [todo_0.0.3.md](todo_0.0.3.md),
установка и обновление — в [руководстве выпуска](docs/RELEASE.md).

- Выпуск публикует три самостоятельных бинарника и `SHA256SUMS`. Нативные проверки до и после публикации сохраняют отчёты в GitHub Actions. Оригинальные лицензии доступны через `doctor --licenses`.
- Сборки по умолчанию рассчитывает оригинальный PoB на LuaJIT. Движок устанавливает PoB при первом запуске расчёта или сервера. Для пользователя достаточно бинарника Go и доступа к GitHub при первой установке.
- Первая установка загружает проверенный PoB v0.23.1 по закреплённой контрольной сумме. Новые стабильные версии PoB доступны через `update`.
- Отмена установки до смены активной версии сохраняет прежний PoB. Релизная проверка охватывает параллельный запуск на чистом кэше и повторный расчёт без доступа к GitHub.
- Расчёты с явно выбранной локальной копией PoB сохраняются в сессиях и доступны через CLI, MCP и gRPC. Результат помечает локальный источник.
- При восстановлении базы v0.0.2 старые запросы расчёта возвращают исходные результаты Go. Новый запрос сохраняет результат оригинального PoB, а оба ответа доступны после перезапуска.
- `update` в CLI, MCP и gRPC проверяет и устанавливает стабильные выпуски PoB2Engine и Path of Building PoE2. После обновления работающий сервер переключается на новый выпуск при перезапуске.
- `doctor` в CLI, MCP и gRPC показывает установленные и доступные версии обоих компонентов, сведения о сборке, целостности каталога, сервере и файле базы.

## [0.0.2] - 2026-11-21

Второй самостоятельный выпуск Go-движка. Границы расчётов и поддержанные входы описаны в [документации версии](https://github.com/Hecatoncheir/pob2_engine/blob/v0.0.2/docs/COVERAGE-0.0.2.md).

### Добавлено

- Каталог и предпросмотр Rapid Casting I и Controlled Destruction в полной выбранной группе через CLI, MCP и gRPC. Предпросмотр возвращает изменения показателей без записи сессии.
- Проверки конфликтов, отмены, резервного копирования и восстановления сессий трёх умений. При обновлении базы `0.0.1` сохраняются исходные результаты запросов и текущий снимок сессии.
- Архивы Windows x64, Linux x64 и macOS arm64 с примерами XML, документацией, лицензиями и контрольными суммами SHA-256.

### Исправлено

- MCP-схемы результатов допускают `stats: null` при неподдержанном расчёте.
- Генерация Dart API использует закреплённые зависимости из lock-файла.

## [0.0.2-rc.1] - 2026-11-21

Кандидат второго выпуска самостоятельного Go-движка. Поддерживаются
[объявленные попадания трёх умений](docs/COVERAGE-0.0.2.md), восемь базовых
классов, каталог и предпросмотр двух поддержек. Flutter остаётся отдельным этапом.
Условия проверки архивов описаны в [приёмке кандидата](docs/ACCEPTANCE-0.0.2.md).

### Добавлено

- Проверка релизного архива на трёх умениях через CLI/MCP/gRPC, девять MCP-инструментов, каталог, обе поддержки, неизменяемое сравнение, экспорт и восстановление трёх сессий.
- Приёмка обновления настоящей базы опубликованного `0.0.1`: новый набор данных, исходный ответ прежнего запроса, сохранение текущего снимка и повторный запуск. XML трёх умений и неизменённый эталон обновления включены в архив.

- Измерения трёх минимальных умений и шести предпросмотров поддержек в памяти: пять повторений, проверка успешного результата и неизменности сессии, исходный вывод и состав среды в Linux CI. Транспорт, дисковая запись и холодный запуск не входят в замеры; сравнение с Lua не заявляется.
- Закреплены 45 результатов Linux CI: на измеренной VM медианы расчёта 139,6–141,4 мкс, предпросмотра 1248,6–1262,6 мкс; исходные файлы, хеши, состав среды и границы включены в отчёт производительности.

- Руководство CLI/MCP для трёх умений и полная матрица 46 инструментов закреплённого прежнего MCP: девять инструментов движка, ограниченные аналоги и отсутствующие функции, включая отложенную интеграцию Flutter.
- Уточнены границы классов, групп, пассивов, предметов, условий и статусов; обновлены описания каталога/предпросмотра, источников, лицензий и примеры без изменения рабочего кода.

- Процессная приёмка сессий Fireball/Frostbolt/Spark: импорт CLI, правка MCP, расчёт gRPC, события, конфликты, точные повторы и восстановление общей резервной копии после Kill.
- 18 случаев отмены через три адаптера до/после commit и 6 аварийных остановок на границе записи с потерей ответа; проверяются исходные результаты, отсутствие повторных записей и лишних событий. Формат журнала остаётся 2, новая миграция не требуется.
- Отчёт сложности этапа 6.2: 46 новых/изменённых функций, максимум COG 8; рабочий сервер не получает тестовых задержек или флагов.

- Общий каталог камней, классов, баз и пассивов через CLI/MCP/gRPC: ограниченный поиск, страницы, точные ID/псевдонимы и границы покрытия.
- Предпросмотр Rapid Casting I и Controlled Destruction в полной выбранной группе: совместимость, повтор семейства, показатели и дельты; общая очередь, без новой ревизии, события или записи журнала. Девять проверок по прежним эталонам Lua и процессный паритет трёх адаптеров.
- Совместимые Protobuf-методы GetCatalog/PreviewSupport и обновлённый Go/Dart API; Flutter не изменяется.

- Правила читаемости и отчёт когнитивной сложности этапа 4: 62 новые/изменённые функции, максимум COG 9; упрощены выбор наборов, проверка XML, чтение дерева и подготовка эталонов.

- Базовые характеристики и ресурсы восьми классов без возвышений: 168 вариантов Lua с уровнями 1/20/50/100 и границами требований камней; чужие пассивы остаются неподдержанными.
- Пять эталонов выбора групп и наборов; процессная проверка MCP/gRPC/CLI, событий, сохранения выбора после Kill и исходных ответов запросов.
- Проверки внутренних идентификаторов класса/возвышения, атомарный отказ выбора набора без главной группы, сохранение расширений неактивных групп и известных настроек поиска PoB.

- Общее ядро попаданий трёх стихий: Frostbolt Projectile и Spark Base, соответствующие свойства/сопротивления и промежуточные показатели; прежние ключи и числа Fireball сохранены.
- Схема данных 2 с явной стихией и режимом, воспроизводимым экспортом и новым ID; 84 отдельных эталона Lua, регрессия 77 прежних случаев и процессные проверки CLI/MCP/gRPC.
- Проверка обновления реальной базы опубликованного `0.0.1`: сохранённые числа/ID данных, новый расчёт и точный повтор прежнего запроса без отката сессии.
- План `0.0.2`: Fireball/Frostbolt/Spark, общий расчёт трёх стихий, базовые классы, каталог, предпросмотр поддержек и совместимость сохранённых сессий. Flutter остаётся за рамками.

### Исправлено

- MCP-схемы результатов допускают `stats: null` при неподдержанном расчёте, включая предпросмотр, сравнение и снимки.
- Dart-плагин генерации запускается с подготовленной конфигурацией пакетов без повторного разрешения зависимостей; lock-файл проверяется перед генерацией.

## [0.0.1-rc.1] - 2026-11-21

Первый кандидат самостоятельного Go-движка. Поддерживается объявленное
покрытие Fireball Projectile; полный паритет с PoB и Flutter не входят в выпуск.

### Добавлено

- Платформенные ZIP с проверяемым составом, документацией, примером и полным комплектом уведомлений; запуск готового архива на трёх ОС до публикации.
- Отчёт измерений расчёта и состава среды Linux в CI.

- Типизированный API полной сборки, правок, результатов и сравнения; поток расчёта с учётом активной задачи до фактического завершения.
- CLI `calculate`, `build import|edit|compare|export`, `storage backup|verify|restore`; JSON, коды статусов и экспорт в новый UTF-8 файл.
- Семь MCP-инструментов, прогресс и полный снимок; одинаковый результат CLI/MCP/gRPC в процессной проверке с восстановлением резервной копии.
- Атомарная замена файла обнаружения Windows при открытом читателе; проверка расчёта с пустым PATH без Python/Lua/PoB.

- Общие команды полной сборки: импорт и правки XML, экипировка, камни, пассивы, условия, расчёт с устойчивым сохранением, экспорт и сравнение без изменения сессии.
- Связь результата с ревизией входа и SHA-256 XML/данных, сброс устаревшего результата и восстановление первоначальных чисел без повторного расчёта.
- Ограниченная очередь, совместное ожидание повторного расчёта, неблокирующий прогресс, отмена и защита от сохранения результата старой ревизии.
- Схема журнала 2 с проверенным переходом из схемы 1 после резервной копии; Backup/Verify/Restore в пакете хранения, проверки сохранности полного XML и расчёта, ограничения истории и объёма записи.
- Расчётная библиотека Go для Fireball Projectile: ресурсы, две поддержки, свойства украшений, начальные пассивы, критические попадания, сопротивления, расходы и DPS; происхождение перенесённых формул сохранено.
- Матрица 77 вариантов Lua с контролем ошибок камней и неразобранных свойств, сравнение 27 чисел и промежуточных значений, статусы и отказ выдавать числа для неподдержанного ввода.
- Неизменяющее сравнение двух документов, проверки параллельных расчётов, отмены и игнорирования сохранённого кэша PoB; предварительные замеры времени и выделений памяти.
- Независимая модель сборки и ограниченный импорт XML: выбор активных наборов, камней, предметов и дерева, сохранение неизвестного содержимого и стабильный SHA-256 канонического документа.
- Проверки повторного обмена XML, неверных ссылок и повреждённого ввода; объявлены границы первого расчётного сценария и статусы complete/partial/unsupported.

- Загрузчик Go без Lua/Python: проверка схемы, сумм, ссылок, идентификаторов и диапазонов; проверки повреждённого и несовместимого набора.

- gRPC `WatchServer`: текущая фаза и уведомление `draining` до штатного EOF, причина остановки, последовательность одного запуска и верхняя граница ожидания.
- Фазы `starting` → `ready` → `draining` → `stopped`, защита переходов и проверки гонок подписки с остановкой без Flutter.
- Ограничение ожидания закрытия хранилища: таймаут не освобождает профиль преждевременно; ошибки очистки сообщаются клиенту и CLI.
- Проверки зависшего хранилища и медленной подписки, доставка уведомления отдельному gRPC-клиенту и процессное восстановление после shutdown.
- Поток `WatchSession`: начальный снимок, правки по ревизиям, восстановление пропущенных событий после перезапуска; отказ записи и повтор команды не создают событий.
- Приватный режим `connect --connection-json` для gRPC-клиента Flutter с общей арендой и штатным освобождением по EOF.
- Проверки порядка событий, медленного читателя, авторизации, остановки и доставки правок CLI/MCP после восстановления.
- Транзакционный журнал bbolt `v1.5.0`: сохранение сессий, ревизий и исходных результатов команд перед успешным ответом CLI/MCP, восстановление после перезапуска и `Kill`.
- Отдельный каталог данных `--data-dir`, сохраняемый профиль `default`, явный временный режим `--ephemeral`, путь и режим хранения в `info`.
- Проверки версии схемы, контрольных сумм и восстановления; отказ от сброса повреждённых данных и от подключения профиля к серверу без сохранения.
- Модульные и процессные тесты восстановления, повторов, параллельных записей, отказа сохранения и эксклюзивного доступа к базе.
- Обнаружение и явный автозапуск сервера по профилю: атомарный файл подключения, проверка экземпляра и протокола, системные блокировки и восстановление устаревших записей, включая повторное использование порта посторонним сервером.
- Защита каталога профиля и токена правами пользователя, включая DACL Windows; удаление только своего файла подключения после завершения сервера.
- Аренды клиентов UI/MCP/CLI, heartbeat, очистка после аварийного отключения и автоматическая регистрация Go-клиента.
- Автоматический режим жизни: уход последнего клиента, ожидание активных RPC и фоновых задач, задержка переподключения и сохранение постоянного режима.
- Ограниченное ожидание фоновых задач при shutdown, отмена контекста при принудительной остановке и процессные проверки конкурирующего запуска и замены завершающегося экземпляра.
- Рабочий каркас Go 1.27.4: CLI, локальный gRPC-сервер и MCP stdio на официальном Go SDK.
- Общий сервис сессий в памяти: создание, снимок, переименование, ревизии и защита от повторного применения успешных команд.
- Первый Protobuf-контракт и воспроизводимая локальная генерация Go/Dart API с закреплёнными инструментами и Dart lock-файлами.
- Проверка токена и версии протокола, постоянный режим сервера, готовность, ограниченное по времени завершение, attach и standalone MCP.
- Модульные и процессные тесты общего состояния CLI/MCP, конфликтов, повторов, ошибок подключения и завершения; проверки контракта и Dart API в CI.
- Согласованную архитектуру отдельного движка на Go, CLI, встроенного MCP и связи с Flutter через gRPC / Protobuf.
- Требования к общей сессии, управлению приложением, автоматическому запуску сервера, учёту клиентов и graceful shutdown.
- План постепенного переноса расчётов PoB, импорта данных, сравнения с исходным Lua и обновлений с откатом.
- CI только на Linux: документация, анализ, тесты Go и проверка гонок; кросссборки Windows x64, Linux x64 и macOS arm64 без cgo выполняются только при выпуске по тегу.
- Выпуск по тегам `v*`: проверку changelog, архивы исходников, контрольные суммы и сборки CLI после появления Go-программы.

Go рассчитывает объявленный набор Fireball; общий сервис сохраняет полную сборку и расчёт, операции доступны через CLI/MCP/gRPC. gRPC проверяется независимо; наработки Flutter сохранены как черновик в `pob2_ui/1.x.x`, подключение и приёмка приложения отложены до готовности движка. Сессии профиля сохраняются на диск и восстанавливаются после перезапуска. Выпусков с работающим расчётным движком пока нет.
