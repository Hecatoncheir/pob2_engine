# План выпуска pob2_engine 0.0.6

Цель выпуска — проверить новую версию PoB до её активации и дать возможность
вернуться к прежней установке, сохранив сборки и ответы запросов. Основа —
[выпущенный v0.0.5](testdata/releases/0.0.5/README.md), PoB v0.23.1 и
[десять эталонных состояний](testdata/reference/0.0.5/README.md). Целевые
платформы — Windows x64, Linux x64 и macOS arm64. Подключение Flutter
остаётся отдельным этапом.

На момент подготовки `v0.23.1` был последним стабильным PoB. Для проверки
перехода и отката закреплены `v0.23.0` и `v0.23.1`. Основной эталон расчёта
и замеров остаётся на `v0.23.1`.

## 1. Воспроизводимые замеры задержки

- [x] **1.1.** Повторить [замеры Windows](testdata/performance/0.0.5-windows/README.md)
  для выпущенных `v0.0.4` и `v0.0.5` с одним PoB, одинаковыми XML и условиями.
  Чередовать версии, записать среду и хеши бинарников. Для трёх сборок
  зафиксировать первый запрос, сырые повторные замеры и медиану.
- [x] **1.2.** Отдельно измерить расчёт на прогретом LuaJIT, запрос gRPC
  и сохранение результата. Сопоставить вклад каждого этапа с полным
  запросом через CLI. Проверить прежде всего Witch и Warrior, где обнаружена
  разница. Исправить подтверждённую регрессию в движке или описать, на каком
  этапе воспроизводится разница и насколько устойчивы замеры.
  [Повторные замеры](testdata/performance/0.0.6-windows/README.md) разделяют
  CLI, RPC с диском и памятью, повтор сохранённого запроса и запись журнала.

## 2. Проверка кандидата PoB

- [x] **2.1.** Закрепить для приёмки базовый и более новый официальные
  выпуски PoB. Записать версии, ревизии, размеры и SHA-256 пакетов. Повторное
  выполнение CI должно использовать те же исходники и нативные библиотеки.
- [x] **2.2.** Воспроизвести десять состояний из `0.0.5` независимым
  запуском оригинального PoB для каждой ревизии. Сопоставить с двигателем
  на той же ревизии выбранные группы и наборы, DPS, показатели защиты,
  статусы, предупреждения и неподдержанные свойства. Использовать объявленные
  допуски и различать нулевой и отсутствующий показатель.
- [x] **2.3.** Сформировать отчёт об изменениях между версиями PoB.
  Зафиксировать версию дерева, доступность использованных камней и предметов,
  числовые изменения и диагностику по каждому сценарию. Расхождение движка
  с оригинальным PoB той же ревизии считать регрессией. Изменения, которые
  воспроизводит сам PoB, отражать как изменения версии.
  [Эталоны и манифесты](testdata/reference/0.0.6/README.md) фиксируют одинаковые
  числа, выбранные группы и диагностику на проверенных состояниях.

## 3. Активация, диагностика и откат

- [x] **3.1.** Распаковывать пакет в отдельный каталог и проверять его до
  смены указателя активной установки. Расширить существующий пробный запуск
  проверкой загрузки каталога и расчётом закреплённых многогрупповых сборок.
  Пользовательская проверка выполняется поставляемым движком и LuaJIT.
  Независимый эталонный прогон выполняется в CI.
- [x] **3.2.** Проверить отказ при неверном хеше, сбое запуска или расчёта,
  отмене, прерывании записи и одновременном обновлении. Обновление должно
  завершиться одной проверенной установкой либо сохранить активную версию.
  Проверить повтор той же операции после сбоя.
- [x] **3.3.** Реализовать явный откат управляемой установки PoB к предыдущей
  рабочей версии. Использовать общий сервис для CLI, MCP и gRPC. Проверить
  откат без сети через локальный CLI, в том числе когда сервер с новой
  версией PoB не запускается. Применять смену версии при перезапуске процесса.
- [x] **3.4.** В `doctor` и ответе обновления показывать установленную версию,
  версию расчёта работающего процесса, предыдущую доступную установку и
  необходимость перезапуска. Возвращать причину отказа или отката через
  действующий контракт либо его обратно совместимое расширение. Сохранить
  поведение `update --check` и обновления бинарника движка.
- [x] **3.5.** Взять базу сессий из опубликованного `v0.0.5`. В одном профиле
  пройти обновление, перезапуск, новый расчёт, откат и ещё один перезапуск.
  Сверить XML и историю ревизий, исходный ответ `request_id` и результаты,
  записанные до и после смены PoB. Новый результат должен указывать ревизию
  PoB, которая его рассчитала.
  [База v0.0.5](testdata/compat/0.0.5/README.md) прошла цикл обновления и отката
  локально на Windows, включая точное восстановление ответов запросов.
