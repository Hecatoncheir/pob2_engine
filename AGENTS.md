# Repository Guidelines

## Состояние и структура проекта

`pob2_engine` — проект расчётного движка Path of Exile 2 на Go. Работают сессии CLI/gRPC/MCP, обнаружение, аренды, сохранение и подписки. Библиотека расчёта Fireball проверяется по Lua; подключение к командам ещё выполняется. Контракты: `docs/SESSION-API.md`, `docs/SERVER-LIFECYCLE.md`, `docs/SESSION-STORAGE.md`, `docs/SESSION-EVENTS.md`.

- `README.md` — архитектура и согласованные требования.
- `TODO.md` — дорожная карта; `todo_0.0.1.md` — план выпуска.
- `CHANGELOG.md` — изменения и записи выпусков.
- `.github/workflows/ci.yml`, `release.yml` — проверки и публикация по тегам.

Используйте `cmd/pob2-engine/` для точки входа, `internal/application/` для команд, `internal/domain/` для моделей, `internal/transport/` для адаптеров, `internal/integration/` для процессных тестов, `api/pob2/v1/` для Protobuf и `gen/go/`, `gen/dart/` для генерируемого API. Дополнительно: `internal/lifecycle/`, `internal/discovery/`, `internal/host/`, `internal/storage/`, `internal/privatefs/`.

## Сборка, проверки и локальная разработка

Используйте Go 1.27.4 и `git diff --check`. CI дополнительно проверяет документацию, ссылки и структуру.

Выполняйте из корня:

```shell
gofmt -w .
go vet ./...
go test ./...
go build ./cmd/pob2-engine
go run ./cmd/pob2-engine --help
```

Это форматирование, анализ, тесты, сборка, справка. CI выполняет тесты и `go test -race ./...` на Linux. Сборки платформ — по тегам `v*`. Работают `serve`, `connect`, `info`, `session`, `mcp`, `shutdown`. При изменении `.proto` нужны Buf 1.73.0 и Dart 3.14.0: выполните `go run ./tool/generate`, затем `go run ./tool/generate -check`. Версии плагинов закреплены; Dart-зависимости сохраняйте в lock-файлах.

Проверяйте лицензии через `python tool/notices.py`. Эталон Lua:
`python tool/reference_lua.py --prepare`; исходники и runtime изолированы в
игнорируемом `.reference/`. Условия и обновление эталонов — в `testdata/reference/README.md`.

## Стиль кода и именование

Документацию, пояснения и комментарии пишите по-русски. Для Go используйте `gofmt` с табуляцией, короткие имена пакетов в нижнем регистре и стандартное именование экспортируемых идентификаторов (`SessionService`). В YAML сохраняйте отступ в два пробела. Делайте функции короткими, зависимости явными, когнитивную сложность минимальной. Генерируемый API обновляйте через воспроизводимую генерацию.

## Тестирование

Используйте стандартный пакет Go `testing`: файлы `*_test.go`, функции `TestXxx`. Процессные тесты включены в `go test ./...`. Порог покрытия пока не установлен. Для расчётных изменений добавляйте воспроизводимые примеры в `testdata/`, закрепляйте ревизию Lua PoB, условия и числовые допуски. Сравнивайте также предупреждения и неподдержанные модификаторы. Совпадение с PoB не означает проверку в игре.

## Коммиты и запросы на слияние

Используйте русские заголовки коммитов с глаголом: «Добавить…», «Исправить…». Ограничивайте коммит одной задачей.

В запросе на слияние опишите результат, связь с этапом TODO или задачей, выполненные проверки и ограничения. При изменении требований обновляйте README и TODO; изменения для выпуска записывайте в раздел «Не выпущено» CHANGELOG. Теги `vX.Y.Z` запускают публикацию и требуют соответствующей записи версии.

## Архитектурные ограничения

Ядро не зависит от Flutter, gRPC и MCP. Все адаптеры используют общий сервис команд и явно выбранную сессию. Неподдержанные возможности возвращают явный статус; заимствования сохраняют происхождение и применимые лицензии.

Публикуйте события после commit, исключая повторы. Повреждённые данные не сбрасывайте. Восстанавливайте результаты `request_id`.
