# План выпуска pob2_engine 0.0.9

После [0.0.8](todo_0.0.8.md) в общей сборке можно сравнить и добавить
поддержку. Следующий сценарий — примерка предмета. Пользователь выбирает
слот, вставляет текст нового предмета или снимает текущий, сравнивает
показатели и подтверждает правку. Изменение видно всем клиентам сессии.

## 1. Примерка в движке

- [x] Использовать существующую правку `equipment` в `CompareBuild` и
  `ApplyBuild`. Менять ссылку на предмет в одном слоте активного набора.
  Сохранять прежние предметы в XML, остальные слоты, наборы и расширения.
  Пустой текст означает снятие предмета. Для допустимого слота, которого
  ещё нет в XML, создать запись и при необходимости пустой набор.
- [x] Проверять базу предмета и совместимость со слотом средствами
  оригинального PoB на снимке выбранной сборки. Возвращать явную ошибку при
  неизвестной базе или несовместимости. Нераспознанные свойства показывать
  в диагностике сравнения. Объявить возможность `build.equipment_preview`
  для клиента сессии, который использует Lua.
- [x] Проверить через CLI, MCP и отдельный gRPC-клиент успешную замену,
  снятие, несовместимость, сохранность XML, совпадение хешей предпросмотра
  и применённой правки. Проверить конфликт ревизий, одно событие при записи
  и точный повтор `request_id` после перезапуска. Сверить характеристики и
  диагностику с оригинальным PoB на закреплённой версии. [Эталон](testdata/reference/0.0.9/README.md).

## 2. Общая сборка в PoB II

- [x] В окне общей сборки ветки `1.x.x` показывать экипировку активного
  набора. Для примерки выбрать штатный слот брони или украшений,
  вставить текст предмета либо снять текущий и сравнить показатели.
  Показывать предупреждения и причину отказа. Оружие, гнёзда и зависимые
  слоты будут отдельным этапом интерфейса.
- [x] Применять только просмотренные слот и текст для той же сессии,
  ревизии и подключения. После правки извне, смены текста или переподключения
  требовать повторную примерку и подтверждение. Обновлять окно по
  `WatchSession`. Расчёт формировать для новой ревизии, экспорт XML
  оставлять явным действием.

## 3. Приёмка выпуска

- [x] Сначала принять движок независимо от Flutter. Проверить открытие
  базы `v0.0.8` с прежним XML, расчётом и ответами `request_id`, а также
  совместимость Protobuf. На Windows сохранена и повторно открыта сессия
  из скачанного `v0.0.8`, сверены снимок, точный повтор расчёта и хеш примерки.
  Схема и сгенерированные Go/Dart API совпадают с `v0.0.8`.
- [x] На Windows x64, Linux x64 и macOS arm64 пройти примерку, отмену и
  применение из PoB II. Сверить состояние через MCP, включая смену
  ревизии во время предпросмотра. Сквозные проверки прошли на трёх
  платформах с PoB v0.23.1, MCP v0.23.0 и кандидатом `v0.0.9-rc.2`.
- [x] Подготовить CHANGELOG, опубликовать кандидат и принять скачанные
  бинарники на трёх платформах. [Приёмка кандидата](testdata/releases/0.0.9-rc.2/README.md).
- [x] Выпустить финальный тег. Проверить нативные сборки, SHA-256
  опубликованных файлов и запуск скачанных бинарников на трёх платформах.
  Все 15 заданий выпуска прошли. [Итоговая приёмка](testdata/releases/0.0.9/README.md).
