# План pob2_engine

Согласован 20 ноября 2026 года. Реализован первый сервис сессий Go/CLI/gRPC/MCP; расчётное ядро ещё не начато. Архитектура и исходные ревизии описаны в [README.md](README.md), изменения фиксируются в [CHANGELOG.md](CHANGELOG.md).

Отмечать задачу выполненной нужно по её проверяемому результату. Подготовка контракта, работающая заглушка, сравнение расчётов PoB и испытание в игре — разные результаты.

## 0. Согласованные решения

- [x] Название проекта и репозитория: `pob2_engine`.
- [x] Язык движка, CLI и встроенного MCP: Go.
- [x] Связь с существующим Flutter-приложением: gRPC / Protobuf.
- [x] Один сервис владеет состоянием; UI, CLI и MCP используют общие команды и явно выбранные сессии.
- [x] Движок работает без Flutter и графического окна.
- [x] Flutter подключается к существующему серверу или запускает его при отсутствии.
- [x] Автоматически запущенный сервер завершается после отключения всех клиентов и окончания задач; вручную запущенный постоянный сервер остаётся работать.
- [x] Аренды клиентов, защита одновременного запуска и graceful shutdown входят в обязательные требования.
- [x] Источник правил и эталон — Lua PoB; алгоритмы переносятся постепенно, данные импортируются автоматически там, где это возможно.
- [x] Публичный репозиторий, README, TODO, CHANGELOG и выпуск через GitHub Actions по тегу `v*` входят в начальную подготовку.

Первый сквозной сценарий реализован: CLI создаёт сессию → отдельный MCP-процесс переименовывает сборку → CLI видит тот же снимок. Проверяются конфликты ревизий, точные повторы команд, токен, несовместимый протокол, остановка сервера и EOF MCP. Рабочие команды и ограничения — в [SESSION-API](docs/SESSION-API.md). Расширенный контракт расчётов, `UiBridge`, хранение и автоматический запуск остаются открытыми задачами.
