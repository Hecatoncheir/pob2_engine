# План выпуска pob2_engine 0.0.4

Цель — использовать каталог установленного оригинального PoB для поиска,
редактирования и предпросмотра сборок через CLI, MCP и gRPC. В режиме LuaJIT
список доступных камней больше не ограничивается Fireball, Frostbolt, Spark
и двумя поддержками. Источник данных в ответе должен совпадать с источником
расчёта. Прежний режим Go сохраняет объявленное ограниченное покрытие.

Платформы выпуска — Windows x64, Linux x64 и macOS arm64. Основой является
завершённый выпуск 0.0.3. Flutter остаётся следующим отдельным этапом.

## 1. Каталог оригинального PoB

- [x] **1.1.** Извлекать камни, базовые классы, базы предметов и пассивы
  из Lua-данных активной установки PoB без изменения её исходников.
  Сохранять точные ID, имена, псевдонимы, допустимые уровни и источник.
- [x] **1.2.** Передавать запросы через существующий процесс LuaJIT.
  Соблюдать отмену, ограничение размера ответа и восстановление процесса.
  Кэшировать только успешно загруженный каталог в пределах данной установки.
- [x] **1.3.** Сохранить поиск, сортировку, страницы и прежние виды каталога.
  Метаданные должны показывать версию, ревизию, SHA-256 и версию дерева PoB.
  Локальная копия PoB явно помечается как локальный источник.

**Приёмка:** поиск находит камни за пределами трёх прежних умений и двух
поддержек, базы оружия/брони и узлы за пределами прежней цепочки Sorceress.
CLI, MCP и gRPC возвращают одинаковые страницы и происхождение данных.

## 2. Правки и предпросмотр

- [x] **2.1.** Разрешать камни полного каталога при изменении групп.
  Проверять идентификатор, уровень и качество; сохранять остальные группы,
  наборы и неизвестные XML-расширения.
- [x] **2.2.** Использовать классы и идентификаторы пассивов активного PoB
  для правки дерева. Не подменять неизвестный узел молчаливым удалением.
  Каталог предметов должен соответствовать исходникам расчёта; правка
  экипировки сохраняет оригинальный текст предмета и выбранный слот.
- [x] **2.3.** Предпросматривать поддержки полного каталога, задавая уровень
  и качество. Проверять существование поддержки и допустимые параметры;
  результат и предупреждения получать из оригинального PoB.
- [x] **2.4.** Сохранять отсутствие записей и событий при предпросмотре
  и сравнении. Неподдержанные модификаторы и предупреждения остаются явными.

**Приёмка:** новая активная способность и новая поддержка добавляются через
API и рассчитываются оригинальным PoB. Предпросмотр меняет показатели,
сохраняя XML, ревизию и исходный результат сессии. Старый режим Go возвращает
прежние ограничения и числовые эталоны.

## 3. Совместимость и устойчивость

- [x] **3.1.** Сохранить совместимость Protobuf и обновить генерируемые
  Go/Dart API воспроизводимой генерацией. Новые параметры имеют прежние

- [x] **3.2.** Восстанавливать сессии и точные ответы `request_id` версии

  Проверять целостность сохранённого XML, ревизий и результатов.
- [x] **3.3.** Проверить параллельные поиск, расчёт и правку, отмену первого

  каталога не должна превращаться в постоянный пустой каталог.
- [x] **3.4.** Добавить процессные проверки CLI/MCP/gRPC с новой способностью,

  предупреждения и ограничения; сравнение с PoB не означает проверку в игре.

Локально пройдены `go vet`, `go test ./...` с процессными тестами,
расчёты LuaJIT, проверка независимых эталонов, формат/lint/совместимость
Protobuf, воспроизводимость Go/Dart API, анализ Dart, лицензии и ссылки.
Сквозная проверка Windows использовала подготовленную локальную копию PoB;
нативная приёмка пакета на трёх ОС остаётся в пунктах 4.3–4.4.
[Отчёт сложности](testdata/quality/0.0.4.json): 102 функции, максимум COG — 10.

Границы: автоматический подбор экипировки, построение пути по дереву,
редактор возвышений, управление Flutter и полный перечень механик игры
не входят в этот выпуск. Каталог показывает данные PoB; возможность расчёта
конкретной сборки подтверждается её результатом и диагностикой оригинального PoB.
