# План выпуска pob2_engine 0.0.3

Цель выпуска — перейти с ограниченного расчёта Go на оригинальный Path of
Building PoE2 под LuaJIT. Пользователь скачивает бинарник под свою ОС, запускает
первый расчёт и после установки PoB может продолжить без сети. CLI, MCP и gRPC
работают с общей сессией и показывают версию расчётного движка. Базовый выпуск
для проверки совместимости — [v0.0.2](testdata/releases/0.0.2/README.md).

Целевые платформы — Windows x64, Linux x64 и macOS arm64. Прежний расчёт
Go сохраняется для регрессионных сравнений. Flutter и эксперименты с
WebAssembly выходят за рамки этого выпуска.

## 1. Воспроизводимая установка PoB

- [x] **1.1.** Закрепить пакет PoB для первой установки по версии, ревизии,
  размеру и SHA-256. Нативная приёмка сверяет версию и ревизию фактического расчёта
  с [эталоном](testdata/reference/sources.lock.json). Локальные тесты проверяют
  прямую загрузку v0.23.1, отказ при неверном архиве и выбор последнего выпуска
  при явной проверке обновлений. Реальная загрузка входит в пункт 1.2.
- [x] **1.2.** Проверить полный цикл установки на чистом кэше, повторного запуска
  без сети и параллельного старта. Сбой скачивания или пробного запуска
  оставляет предыдущую версию и пользовательские сессии доступными.
  Тесты установщика проверяют одну загрузку за два запуска, сбой загрузки
  и отмену перед активацией. Windows прошёл расчёт и `doctor` с заранее
  заполненным кэшем и заблокированным GitHub. Загрузка официального архива
  с чистого кэша включена в релизную проверку.
- [x] **1.3.** Прогнать проверку запуска на трёх целевых ОС. Сохранить в отчётах
  версию PoB, ревизию и контрольную сумму загруженного пакета. В отчёт
  также включены результаты параллельного запуска и повторного расчёта офлайн.

## 2. Расчёты и границы API

- [x] **2.1.** Сравнить результаты CLI, MCP и gRPC с оригинальным PoB для
  Fireball, Frostbolt и Spark. Включить правку конфигурации, смену набора
  и предпросмотр поддержки без изменения сохранённой сборки.
  Локальные проверки на LuaJIT охватывают все три умения, правки через MCP,
  точный повтор сохранённого ответа через gRPC, смену набора Druid и
  предпросмотр Rapid Casting I. Сквозная проверка CLI/MCP/gRPC через TCP
  включена в релизный сценарий.
- [x] **2.2.** Проверить примеры с предупреждениями камней и
  неподдержанными модификаторами. Зафиксировать, какие операции редактирования
  и каталога ещё ограничены встроенными данными Go. Локальный LuaJIT вернул
  `partial` с ожидаемыми кодами `pob_warning` и `unsupported_modifier`.
  Границы правок и поиска описаны в [CATALOG.md](docs/CATALOG.md).
- [x] **2.3.** Проверить восстановление базы из v0.0.2. Сохранённые результаты
  и повтор с прежним `request_id` воспроизводятся. Новый расчёт возвращает
  показатели и метаданные LuaJIT.
  [Эталон v0.0.2](testdata/compat/0.0.2/README.md) восстановлен на Windows.
  Проверены оба ответа после повторного открытия базы. Этот же переход
  добавлен в нативные сценарии кандидата.
- [x] **2.4.** Проверить отмену длительного расчёта и запуск нового процесса
  LuaJIT после отмены. Измерить время готовности и медиану повторных
  расчётов на одной и той же паре версий движка и PoB.
  На Windows тест с зависшим LuaJIT подтвердил остановку процесса при отмене
  и успешный расчёт Fireball в новом процессе. Релизный сценарий записывает
  время готовности сервера, первый запрос и пять повторных расчётов каждого
  умения для Go и LuaJIT. Замеры кандидата на трёх ОС входят в пункт 4.2.

## 3. Обновление и диагностика

- [x] **3.1.** Проверить `doctor` и `update` через CLI, MCP и gRPC для целей
  `engine`, `pob` и `all`. Установленная версия PoB видна при отсутствии
  сети. После обновления диагностикой можно подтвердить версию после перезапуска.
  Тесты без сети покрывают все три цели через локальные CLI/MCP и gRPC.
  Релизный сценарий сверяет установленную версию PoB в `doctor` и `update`
  при недоступности GitHub.
- [x] **3.2.** Проверить замену бинарника и отказ при несовпадении SHA-256.
  Описать переход с архивов v0.0.2 на бинарники v0.0.3 и восстановление
  при прерванном обновлении.
  Замена запущенного файла и отказ при неверном SHA-256 проверены на Windows.
  Переход и восстановление описаны в [RELEASE.md](docs/RELEASE.md).
- [x] **3.3.** Проверить установку нового PoB отдельно от бинарника. Зафиксировать
  действия при сбое и способ возврата к рабочей версии PoB с сохранением сессий.
  Тест менеджера с локальными пакетами проверяет обнаружение обновления,
  активацию при следующем запуске и сохранение предыдущего каталога.
  Порядок временного возврата описан в [RELEASE.md](docs/RELEASE.md).
