# План выпуска pob2_engine 0.0.7

Цель выпуска — открыть XML-сборку в общей сессии PoB II, поменять уровень
персонажа через MCP или из окна и получить расчёт для той же ревизии сборки.
Основа — [выпущенный v0.0.6](testdata/releases/0.0.6/README.md) и
[проверенное на Windows двустороннее переименование](https://github.com/Hecatoncheir/pob2_ui/commit/6f03c8e53cf926298fdd2f8d6616958631ea8715)
в ветке `pob2_ui/1.x.x`. Движок уже передаёт XML и расчёт в подписке.
Клиент PoB II пока применяет только имя.

## 1. Создание общей сессии из XML

- [x] Добавить создание сессии с начальным XML одной командой через CLI и gRPC.
  Проверить XML до записи, сохранить документ в первой ревизии и опубликовать
  снимок после записи. Ошибка разбора или хранения оставляет идентификатор
  сессии свободным для повтора. Сохранить поддержку создания пустой сессии и
  отдельного импорта через существующие команды.
- [x] Проверить восстановление такой сессии с диска. Точный повтор `request_id`
  возвращает исходный снимок даже после правок и перезапуска. Повтор с другим
  XML и создание с уже занятым идентификатором возвращают конфликт.

## 2. Одна двусторонняя правка в PoB II

- [x] Добавить явное открытие сборки из общей сессии в `1.x.x`. Применять XML
  начального снимка и последующих принятых правок через `WatchSession`.
  Работать с копией в общей сессии. Запись поверх исходного XML требует
  обычного явного сохранения пользователем.
- [x] Подключить изменение уровня персонажа из окна через `ApplyBuild`.
  MCP использует существующий `edit_build`. При конфликте ревизий показать,
  что снимок обновился, и дать пользователю повторить правку явно. После
  переподключения применять события с последней применённой ревизии без дублей.
- [x] Показать сохранённый результат `CalculateBuild`, включая показатель жизни
  и предупреждения PoB, если `calculated_from_revision` совпадает с
  `input_revision`. При ошибке применения XML сохранить последний открытый
  снимок и показать причину в окне.

## 3. Приёмка и публикация

- [x] Расширить сквозной тест PoB II. Создать общую сессию из XML Fireball,
  поменять уровень через MCP и увидеть его в окне, затем поменять уровень из
  окна и сверить снимок в MCP. Выполнить расчёт и сверить ревизию, показатель
  и предупреждения. Повторить после обрыва связи и проверить конфликт двух
  клиентов, сохранность исходного XML и существующее переименование.
  Локальный нативный прогон Windows прошёл.
- [x] Пройти сценарий на Windows x64, Linux x64 и macOS arm64 с одной
  закреплённой версией PoB. Прогнать эталоны Lua, восстановление базы `v0.0.6`
  и совместимость старого Dart-клиента с новым сервером. При изменении схемы
  выполнить проверку совместимости Protobuf с `v0.0.6` и генерацию Go/Dart.
  [Сквозной прогон PoB II](https://github.com/Hecatoncheir/pob2_ui/actions/runs/45061250909)
  прошёл с `v0.0.7-rc.1`, PoB v0.23.1 и клиентом `25a4374` в окне 1280×800.
  Предыдущий клиент `6f03c8e` прошёл процессный тест с новой сборкой движка.
- [x] Проверить кандидат выпуска с нативными бинарниками. Внести изменения в
  CHANGELOG, зафиксировать версии клиента, движка и PoB в отчёте. После приёмки
  опубликовать `v0.0.7` и сверить скачанные бинарники с `SHA256SUMS`.
  [Отчёты кандидата](testdata/releases/0.0.7-rc.1/README.md) подтверждают
  проверку движка на трёх платформах до и после скачивания.
  [Итоговая приёмка v0.0.7](testdata/releases/0.0.7/README.md) содержит
  проверенные SHA-256 и ссылку на нативные отчёты CI.
