# План выпуска pob2_engine 0.0.11

## Что осталось после 0.0.10

В общей сборке PoB II уже можно найти обычный пассив, сравнить путь
назначения или снятия и применить правку. Для новых узлов атрибутов движок
использует выбор PoB по умолчанию. Предпросмотр показывает добавляемые и
снимаемые узлы, а отдельного действия для смены атрибута назначенного
узла пока нет. [План 0.0.10](todo_0.0.10.md) ·
[Итоговая приёмка](testdata/releases/0.0.10/README.md).

Отдельных сценариев общей сборки ждут специализации, мастерства, гнёзда
самоцветов и ветви комплектов оружия. В примерке экипировки также открыты
оружие и зависимые слоты. [Правки дерева](docs/BUILD-COMMANDS.md#правки-xml) ·
[План 0.0.9](todo_0.0.9.md).

## Что взять в 0.0.11

**Выбор и смена атрибута пассива с предпросмотром.** Пользователь выбирает
силу, ловкость или интеллект при назначении узла либо меняет атрибут уже
назначенного пассива. Это завершает сценарий, который 0.0.10 начал с
выбора по умолчанию. Для проверки подходит существующий узел `13397`
в тестовой сборке воина на закреплённом PoB. [Эталон дерева](testdata/reference/0.0.10/README.md).

## 1. Движок и контракт

- [x] Расширить `tree_node` выбором атрибута при назначении и отдельным
  действием для смены атрибута назначенного узла. Обе операции идут через
  `CompareBuild` и `ApplyBuild`. Действия `allocate` и `refund` из 0.0.10
  продолжают приниматься в прежнем формате.
- [x] Определять доступность и текущий выбор средствами оригинального
  Lua PoB. При назначении использовать правило штатного редактора PoB
  для новых узлов атрибутов вдоль пути и отразить их выбор в предпросмотре.
  При смене атрибута уже назначенного узла записать только его новый выбор
  в активной спецификации XML.
- [x] Возвращать в сравнении ID затронутых узлов, прежний и новый атрибут,
  изменения показателей и диагностику. Передать PoB II признак узла с
  выбором атрибута и действующее значение. Сгенерировать Go и Dart API
  с добавочными полями и возможностью обнаружить поддержку операции.

## 2. Приёмка движка до Flutter

- [x] На закреплённом Lua PoB проверить назначение узла `13397` с каждым
  атрибутом, смену уже назначенного атрибута и путь с промежуточными
  узлами атрибутов. Сверить итоговые значения силы, ловкости, интеллекта
  и диагностику с оригинальным PoB. При смене выбранного значения сверить
  состав и порядок узлов, соседние назначения, прочие спецификации и шаги
  экспорта и повторного открытия XML.
- [x] Прогнать сценарии через CLI, MCP и отдельный gRPC-клиент. Проверить
  отказы при выборе атрибута для обычного узла, при неподдерживаемом
  значении и при устаревшей ревизии. Сравнить хеши предпросмотра и
  применённого варианта, проверить одно событие при записи. Предпросмотр
  сохраняет XML, ревизию и расчёт. Повтор `request_id` после перезапуска
  возвращает прежний ответ.
- [x] Открыть сессию из `v0.0.10` с сохранёнными атрибутами и повторить
  прежние команды назначения и снятия. Сверить совместимость Protobuf.

CLI, MCP и отдельный gRPC-клиент проверены на Windows x64 до подключения
Flutter. Повторяемый сценарий и выбранные узлы описаны в
[эталоне 0.0.11](testdata/reference/0.0.11/README.md). Сессия из
опубликованного v0.0.10 открылась с прежним расчётом и ответом сохранённого
запроса. Схемы прошли `buf breaking` относительно тега `v0.0.10`.

## 3. Общая сборка PoB II

- [x] В окне дерева для узла атрибута показать действующее значение и
  выбор силы, ловкости или интеллекта. В предпросмотре показать изменение
  выбора у цели и затронутых узлов пути вместе с показателями сборки.
- [x] Применять просмотренный вариант для той же сессии, ревизии и
  подключения. Если пользователь поменял выбор, пришла правка через MCP
  или приложение переподключилось, запросить новый предпросмотр.
  После подтверждения показать новое значение по событию `WatchSession`.

На Windows x64 пройден настольный сценарий общей сборки с оригинальным Lua
PoB. Тест назначает ловкость двум узлам пути, проверяет неизменность сборки
после предпросмотра и отмены, затем меняет атрибут цели на интеллект и
повторно открывает узел с новым значением. Сценарий включается через
`POB2_ENGINE_TEST_ATTRIBUTES=1` в `engine_session_desktop_test.dart`.
Для локальной проверки PoB II использует Dart API из `gen/dart` через
`pubspec_overrides.yaml`.
Пройдены `go vet ./...`, `go test -p 1 ./...`, `dart analyze` и
`flutter test --no-pub`. Полный прогон Go прошёл при повторе в отдельном
временном каталоге Windows после сбоев очистки в тестах установки и отката.

## 4. Выпуск

- [x] Опубликовать `v0.0.11-rc.1` и закрепить его Dart API в PoB II
  `1.x.x`. Принять назначение и смену атрибута на Windows x64, Linux x64
  и macOS arm64, включая отмену и обновление общей сборки после правки
  через MCP. Включить `POB2_ENGINE_TEST_ATTRIBUTES=1` в приёмке кандидата.
  На Windows включить проверку очистки профиля и отката.
- [Приёмка кандидата](https://github.com/Hecatoncheir/pob2_engine/actions/runs/45119458607)

  прошли на трёх ОС.
- [x] После приёмки опубликовать `v0.0.11`, сверить `SHA256SUMS` и запустить
  скачанные бинарники на трёх платформах. Записать результаты приёмки.

[Итоговая приёмка](testdata/releases/0.0.11/README.md) содержит SHA-256
и отчёты запусков скачанных бинарников на всех трёх ОС.

## Кандидаты на дальнейшие выпуски

- Ветви комплектов оружия и гнёзда самоцветов. Каждому сценарию нужны
  свои эталоны Lua и проверки сохранения связанного снаряжения.
- Мастерства и специализации. Для мастерств первым шагом подобрать
  воспроизводимый пример на штатных данных PoB.
- Примерка оружия, переключение спецификаций дерева и графическое
  представление общего дерева в PoB II.
