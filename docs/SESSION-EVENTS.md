# Изменения сессии в реальном времени

`WatchSession(session_id, after_revision)` — серверный поток gRPC, возможность
`session.events`. Сейчас изменяемое поле одно: `build_name`. Расчёты, экипировка,
дерево и навыки ещё не реализованы; поток не добавляет их поддержку автоматически.

## Снимок и порядок

- `after_revision = 0`: сначала событие `snapshot` с текущим состоянием, затем
  каждая следующая принятая правка без разрыва между снимком и подпиской.
- Ненулевая ревизия: все последующие события по порядку, затем новые правки.
  Клиент запоминает последнюю применённую ревизию и передаёт её при переподключении.
- Ревизия выше текущей возвращает `Aborted`. Клиент явно запрашивает новый снимок.
- Правка `renamed` содержит снимок, `request_id`, `changed_fields = [build_name]`
  и `previous_build_name`, позволяющие показать, что именно изменилось.
- Событие доступно только после успешного commit. Отклонённая команда и точный
  повтор успешного запроса новых событий не создают.

История восстанавливается из сохранённых команд даже после перезапуска сервера.
Она общая для подписчиков и ограничена существующим лимитом 4096 правок сессии.
Медленный читатель не блокирует запись и дочитывает события по ревизиям.

## Подключение Flutter

Интеграция настоящего приложения отложена до готовности расчётного движка.
Ниже описан будущий клиентский контракт; разработка и проверки серверного gRPC
продолжаются независимо от Flutter.

Подписка требует `authorization: Bearer ТОКЕН` и `pob2-lease: АРЕНДА`. Она не
считается вычислительной задачей. Освобождение/истечение аренды и остановка сервера
закрывают подписку; heartbeat выполняется независимо от поступления событий.

Приложение может запустить собранный CLI дочерним процессом:

```shell
pob2-engine connect --profile main --kind ui --start-server --connection-json
```

Первая строка stdout содержит `address`, `token`, `lease_id`, `instance_id` и
`protocol_version`. **Этот вывод содержит секрет: не направляйте его в журналы.**
Обычный `connect` секретов не выводит. Процесс поддерживает аренду до EOF stdin;
Flutter держит stdin открытым и использует выданную аренду для gRPC. Вторая
регистрация приложения не нужна. При отключении Flutter закрывает поток, канал
и stdin; при потере сервера повторяет обнаружение и подписку с последней ревизии.

Изменения UI отправляются тем же `RenameBuild` с ожидаемой ревизией. При неясном
результате повторяют прежние аргументы и `request_id`; конфликт не перезаписывают
автоматически. Выбранная сессия должна соответствовать сборке, открытой в UI.
