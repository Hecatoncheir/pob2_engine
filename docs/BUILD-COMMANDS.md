# Полная сборка в общем сервисе

`application.BuildCommands` расширяет сервис сессий импортом/правками XML,
расчётом, экспортом и сравнением. Все операции используют явно выбранную сессию.
CLI, MCP и gRPC вызывают этот контракт без собственных формул. Примеры
и коды завершения: [CLI-BUILDS.md](CLI-BUILDS.md).

## Команды и состояние

- `Apply`: импорт XML либо одна правка `build.Edit`: уровень персонажа,
  условие, группа камней, добавление поддержки, предмет в слоте, пассивы
  или выбор наборов/оружия.
- `Calculate`: расчёт текущего неизменяемого снимка с сохранением результата.
- `Compare`: расчёт текущего снимка и варианта XML/правки без изменения сессии.
- `Export`: исходный сохраняемый XML, его хеш и текущая ревизия.

`application.CatalogCommands` добавляет поиск текущего каталога PoB и
`PreviewSupport`: сравнение полной выбранной группы после добавления поддержки
с заданными уровнем и качеством в копию. По умолчанию это 1 и 0.
В прежнем режиме Go сохраняются ограниченный каталог и параметры 1/0.
Используются общий расчётчик и та же очередь;
предпросмотр не создаёт ревизию, событие или запись журнала.
Параметры, статусы и примеры — в [CATALOG.md](CATALOG.md).

Импорт, правки и расчёт требуют `expected_revision` и `request_id`. Успешная
команда добавляет одну ревизию и одно событие после commit. Повтор возвращает
первоначальный результат, включая старую ревизию; текущая сессия при этом
не откатывается. Использование ID другой успешной команды отклоняется.

`BuildRevision` меняется при импорте/правке входа. Результат хранит SHA-256 XML,
SHA-256/ID данных и `CalculatedFromRevision`. Правка входа очищает текущий
результат. Переименование сохраняет XML и действующий расчёт. Расчёт, начатый
для старой ревизии, получает конфликт при попытке сохранить результат.

`ViewSnapshot` предоставляет вложенный `build` с моделью и типизированным
расчётом. Внутренний журнал сохраняет исходный JSON результата без пересчёта
при восстановлении: исправление формул не подменяет уже возвращённый ответ
старого `request_id`.

## Правки XML

`Document.Edited` создаёт копию, проверяет правку и возвращает новый документ.
Ошибка не оставляет частичного изменения. Неизвестные части сохраняются;
при полной замене группы заменяются её камни, при замене предмета создаётся
новый ID. Снятие предмета очищает слот и оставляет предмет в документе.
Старый числовой кэш PoB удаляется после правки. Для добавления камней доступны
ID, названия и исторические идентификаторы из закреплённого набора.

`add_support` дописывает включённый камень в текущую расчётную группу
активного набора умений и сохраняет соседние камни и атрибуты группы.
Для проверки совместимости используйте `PreviewSupport` и его диагностику
PoB. Передайте при записи те же ID, уровень, качество и ожидаемую ревизию.
Наличие этой операции gRPC сообщает возможностью `build.add_support`.

## Очередь, прогресс и отмена

Одновременно выполняются до четырёх задач; всего допускаются 20 работающих
и ожидающих команд. Переполнение возвращает `resource_exhausted`.
`WithProgress` передаёт последнее состояние `queued`, `running`, `saving`,
`completed`; медленный читатель не задерживает запись. Для повторного запроса
незавершённой задачи используется `waiting` и общий результат.

Отключение/отмена прерывает ожидание очереди и вычисление до сохранения.
Уже подтверждённая транзакция не откатывается из-за потери соединения.
Аренды и задачи не восстанавливаются после перезапуска; XML, результаты,
ревизии и исходные ответы запросов восстанавливаются из журнала.

Учётный объём сохраняемой истории в памяти ограничен 128 МиБ; это не предел
всей памяти процесса. Журнал ограничен 128 МиБ полезных записей,
одна запись — 8 МиБ. Достижение лимита не удаляет подтверждённые данные.
Можно экспортировать сборки и продолжить в новом профиле. Дополнительно
действуют ограничения XML и 64 КиБ на текст предмета/пользовательских свойств.
