# Переход основной мастерской PoB II на pob2_engine

## Цель

В стабильном PoB II 1.x основная мастерская открывает и редактирует
сборку в сессии `pob2_engine`. Go принимает команды CLI, MCP и gRPC,
проверяет ревизии и сохраняет результат. Оригинальный Lua PoB рассчитывает
сборку и проверяет игровые ограничения. Flutter показывает редактор,
рисует дерево и управляет окнами.

Базой для переноса служат функции редактора ветки `1.x.x` на коммите
`5b3f2119e52aa9761ac3d29302cebf4904527002` и движок v0.0.11.
[Сценарии PoB II](https://github.com/Hecatoncheir/pob2_ui/blob/5b3f2119e52aa9761ac3d29302cebf4904527002/README.md#что-работает) ·
[Приёмка движка](../testdata/releases/0.0.11/README.md).

Ветви оружия выпущены в `pob2_engine v0.0.12` и приняты в общей сборке
PoB II на трёх ОС. [Отчёт этапа 1](../testdata/releases/0.0.12/README.md).

## Этапы

| Этап | Что переносим | Проверяемый результат |
| --- | --- | --- |
| 1. Ветви оружия | Режимы назначения, снятие, предпросмотр и очки для обоих комплектов. [План 0.0.12](../todo_0.0.12.md) | CLI, MCP, gRPC и общая сборка PoB II показывают путь оригинального Lua. |
| 2. Одна сборка в мастерской | Открытие XML в сессии, стабильная привязка к записи библиотеки, просмотр расчёта и первая правка условия. | Правка в штатном редакторе видна через MCP, сохраняется в XML и восстанавливается после перезапуска. |
| 3. Дерево | Геометрия и ресурсы, подсказки, сравнение путей, поиск влияния, мастерства, гнёзда, восхождения и спецификации. | Существующие сценарии дерева проходят на том же XML с совпадением режимов, очков и результатов Lua. |
| 4. Умения, экипировка и условия | Полные формы групп и поддержек, выбор умения и его части, редактор предметов, оружие и зависимые слоты, каталог условий, подробный отчёт. | Предпросмотр, применение и отчёты совпадают для контрольных сборок, включая предупреждения о камнях и предметах. |
| 5. История и библиотека | Undo/Redo через ревизии, применение этапа прокачки одной командой, заметки, копии, коды PoB, ссылки, импорт из оригинального PoB и файловые конфликты. | Старые XML, резервные копии и заметки переживают обновление, правку через MCP, конфликты и восстановление. |
| 6. Инструменты MCP и поставка | Совместимость нужных инструментов редактора, запуск и обновление движка из установщика, проверка профиля и откат. | Установленный PoB II управляет общей сборкой через gRPC, а команды MCP для окон и диалогов работают через приложение. |
| 7. Релиз PoB II 1.x | Кандидат, приёмка на Windows x64, Linux x64 и macOS arm64, стабильный выпуск и проверка скачанных установщиков. | Все сценарии этапов приняты в штатном редакторе на чистом профиле и после обновления предыдущего выпуска. |

## Как принимать перенос

- Для каждого сценария закрепить исходный XML, действие, версию Lua,
  ожидаемые поля, диагностику, изменение файлов и поведение при ошибке.
  Использовать сценарии существующего редактора как эталон.
- Проверять операции сборки через CLI, MCP и gRPC до подключения Flutter.
  Операцию с предпросмотром сверять по состоянию, расчёту и хешу XML.
  Успешная запись даёт одну ревизию и одно событие.
- Проверять запрет применения устаревшего предпросмотра, повтор запроса,
  переподключение, отмену и сохранность XML при внешней правке. Библиотека
  сохраняет переносимые XML, журнал движка восстанавливает сессии и ревизии.
- По мере переноса запускать действующие тесты PoB II с новым сервером.
  Перед релизом принять расчёт, дерево, редакторы, библиотеку, автоматизацию
  MCP, установку, обновление и откат на трёх нативных раннерах.

Промежуточные версии движка можно выпускать после приёмки соответствующего
этапа. Публикация PoB II 1.x опирается на полный набор проверок штатной
мастерской, включая импорт из оригинального PoB через внешний адаптер.

## Открытие сборки и первая сквозная правка

1. Создать общую сессию из XML открытой сборки одним вызовом. Импорт
   использует тот же XML, что и экспорт из мастерской, с заметками и этапами.
   Проверить первую ревизию и повторное чтение XML через gRPC. Этот шаг
   реализован в локальном коммите PoB II `63e8e5d` и проверен
   процессным тестом.
2. Связать запись библиотеки с явным идентификатором сессии и отслеживать
   последнюю применённую ревизию входных данных. При открытии сначала
   принимать состояние сессии, затем подписываться на последующие изменения.
3. Отправить правку условия из существующей формы редактора как типизированный
   `ConfigEdit` с ожидаемой ревизией. После подтверждения принять XML из
   снимка и сохранить через существующую проверку версии файла.
4. Сверить XML, условие и расчёт из мастерской, CLI и MCP. Во время правки
   внести внешнее изменение, проверить конфликт, повторное открытие и принятие
   актуального снимка. При расхождении с файлом показать доступные версии
   средствами библиотеки.

### Приёмка редактора условий

В PoB II `1.x.x` коммит `9f7f4d4` подключает штатный редактор условий к общей
сессии из открытого XML. При подключении к существующей сессии пользователь
отдельно подтверждает применение её снимка к записи библиотеки. Приёмка
использует опубликованный движок `v0.0.12` и штатные Lua и MCP PoB II.

- Тест передаёт уровень противника из MCP в мастерскую, отклоняет сохранение
  из устаревшей формы и проводит новую правку через gRPC. MCP и CLI читают
  обновлённый XML. Снимок содержит расчёт актуального ввода.
- После перезапуска движка тест открывает ту же сессию и сверяет XML из CLI
  с файлом в библиотеке. Отдельная правка файла защищена от перезаписи
  условиями из сессии.
- На Windows локально прошли 297 тестов Flutter, один сценарий пропущен.
  Процессную и нативную проверки с опубликованным `v0.0.12` прошли Windows,
  Linux и macOS в [матрице PoB II](https://github.com/Hecatoncheir/pob2_ui/actions/runs/45158587954).

Планы прокачки остаются в библиотеке PoB II. XML движка сохраняет элементы
сборки, а комментарий плана после корневого элемента отбрасывается при
нормализации. Перенос планов между клиентами относится к этапу 5.

### Первый шаг переноса дерева

В коммите PoB II `3cf363e` обычные пассивы на штатном дереве открывают
предпросмотр `CompareBuild` для текущей ревизии. Применение через `ApplyBuild`
передаёт `TreeNodeEdit`, обновляет снимок в мастерской и сохраняет тот же файл.
При назначении берётся выбранный режим дерева, при снятии используется режим
уже назначенного узла. Предпросмотр для старой ревизии нельзя применить.

- Локально на Windows прошли 299 тестов Flutter, один сценарий пропущен.
  Виджетный тест проверяет клик, отказ по старому предпросмотру и повторное
  подтверждение. Процессный тест назначает и снимает узел в общем режиме
  и обеих ветвях оружия, сверяет расчёт с мастерской, XML — с CLI и MCP.
- Приёмка общей сборки с опубликованным движком `v0.0.12` прошла на Windows,
  Linux и macOS. Отдельная проверка CLI и MCP на Linux прошла с исходниками
  `v0.0.12`. Прежняя ревизия не содержала `CreateSessionFromXml`.
  [Прогон PoB II](https://github.com/Hecatoncheir/pob2_ui/actions/runs/45160155973)

Геометрию, текстуры и подсказки продолжает отдавать штатный Lua. Для
переноса этих данных нужны координаты, связи узлов и ресурсы дерева.

### Мастерства и пустые гнёзда

В закреплённых данных PoB `7d6f530cbdab20389ff8bc6ba97a37ac27f74e41`
проверены деревья `0_1`–`0_5`. Узлов с выбираемыми эффектами мастерства
в этих деревьях нет. Сценарий вернётся в приёмку при появлении таких узлов
в поддерживаемой версии данных.

В движке с возможностью `build.tree_sockets` штатное дерево PoB II
показывает предпросмотр назначения и снятия пустого гнезда. Гнездо
использует общий режим даже при выборе оружейной ветви в интерфейсе.
Занятое гнездо блокирует снятие узла, пока самоцвет установлен.

Процессная проверка движка использует гнездо `26725`, активную спецификацию
[воина](../testdata/reference/0.0.10/warrior.xml) и настоящее Lua PoB.
CLI, MCP и gRPC возвращают одинаковый предпросмотр. Хеш XML после записи
совпадает с предпросмотром. Отдельная проверка закрывает отказ в оружейной
ветви, отказ при устаревшей ревизии и сохранность XML с занятым гнездом.

В PoB II `28a3e55` процессный тест назначает и снимает гнездо `61419`,
когда выбрана ветвь второго комплекта. Он сверяет режим, расчёт Lua и XML
из мастерской, CLI и MCP. На Windows прошли 300 тестов Flutter, один
сценарий пропущен. Проверены локальные сборки движка и интерфейса.

### Установка и снятие самоцветов

Команда `jewel` сохраняет связь с предметом в активной спецификации.
Можно использовать ID существующего предмета, передать текст нового или
снять самоцвет. Lua PoB подтверждает назначенное гнездо и совместимость.
При снятии сохраняются назначенные узлы и список предметов.

Проверка `TestLuaJewelAcrossProcesses` использует гнездо `26725` и Ruby
с `+17% to Fire Resistance`. CLI, MCP и gRPC возвращают один предпросмотр.
Запись совпадает с его хешем, снятие возвращает исходное сопротивление,
а повторная установка сохраняет ID и XML первого применения. Совместимость
сохранённых снимков проверена в Go и в эталонном Lua на Linux.
[Приёмка движка](https://github.com/Hecatoncheir/pob2_engine/actions/runs/45169625427)

В PoB II карточка назначенного гнезда открывается правой кнопкой мыши.
Редактор выбирает предмет из списка, принимает текст и снимает самоцвет
после предпросмотра. Устаревшее сравнение отклоняется. Сохранённый результат
виден в дереве, в файле сборки, через CLI и MCP.

PoB II `ad3159e` закрепляет Dart API по коммиту движка `d4ae538`.
На Windows прошли 302 теста Flutter, один сценарий пропущен. Включены
проверка открытия карточки гнезда и применения в штатном виджете, а также
процессный сценарий с новой сборкой движка и настоящим Lua.

### Переключение спецификаций дерева

Меню «Набор дерева» передаёт `selection.sets.tree` через gRPC для общей
сборки. Lua PoB подтверждает выбранную спецификацию и её класс. Экран
обновляется из принятого снимка и сохраняет XML. Если сборка изменилась
после открытия меню, выбор с прежней ревизией отклоняется.

Эталон [Воина и Ведьмы](../testdata/reference/tree-specs/warrior-witch.xml)
использует дерево `0_5` из PoB `7d6f530cbdab20389ff8bc6ba97a37ac27f74e41`.
CLI, MCP и gRPC совпадают по расчёту и предупреждениям. Сопротивление огню
меняется с 10 до 27, а Lua показывает доступное очко второго комплекта.
После обратного переключения XML совпадает с исходным.

В PoB II (`fb6c818`) на Windows прошли 304 теста Flutter, один пропущен.
Проверены выбор дерева из штатного меню, обновление дерева после команды
MCP и отказ при выборе с устаревшей ревизией. Использованы локальная сборка
движка и та же ревизия Lua PoB.
