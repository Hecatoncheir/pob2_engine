# Расчёт попаданий заклинаний на Go

`internal/calculation.Engine` использует проверенный встроенный набор и
`build.Document`. При расчёте не выполняются Lua/Python, сетевые запросы
или обращения к пользовательским каталогам. Интерфейсы библиотеки:
`Calculate(ctx, document)` и `Compare(ctx, before, after)`.

## Порядок вычислений

1. Проверить выбранные версии, персонажа, условия, группы, поддержки,
   связность пассивов, экипировку и каждый модификатор.
2. Собрать модификаторы в постоянном порядке: поддержки, узлы по ID,
   слоты по имени, строки пользовательских свойств. `BASE` складываются,
   `INC` суммируются, `MORE` перемножаются.
3. Рассчитать характеристики, затем жизнь и ману с округлением до целого;
   регенерацию маны округлить до одного знака. Источник силы и интеллекта
   даёт соответственно жизнь и ману по правилам закреплённого PoB.
4. Округлить множитель скорости до двух знаков. Минимальный и максимальный
   урон выбранной стихии округлить после увеличений и множителей, до критических
   попаданий и сопротивления противника. Controlled Destruction запрещает
   критические попадания; обычный шанс ограничивается диапазоном 0–100%.
5. Рассчитать среднее попадание, частоту применения и DPS. Сопротивления
   персонажа усечь к нулю и ограничить нижней границей PoB и максимумом.

Как в `Common.lua`, округление использует `floor(x * 10^n + 0.5) / 10^n`.
Дробные значения обычных плоских и процентных свойств пока отклоняются;
дробные сопротивления принимаются и усекаются по исходным правилам.
Неизвестный активный ввод даёт `unsupported` и `stats: null`.

Результат содержит точные SHA-256 XML и данных, ID набора, commit PoB,
режим расчёта, показатели, список применённых модификаторов и диагностику.
Сохранённые `PlayerStat` из XML не используются как готовые значения.
Источники перенесённых частей, исходное авторство, лицензия и изменения
перечислены в [origin.json](../internal/calculation/origin.json).

## Сравнение с Lua

[Рецепты](../testdata/reference/cases.recipe.json) и
[эталоны](../testdata/reference/cases.lua.json) охватывают 77 вариантов:
75 полных расчёта, один случай требований камня и один неразобранный Lua
модификатор. Проверяются 27 показателей и промежуточных значений;
неподдержанное свойство проверяется отказом Go выдавать числа.

```shell
python -X utf8 tool/reference_cases.py
go test ./internal/calculation
```

Lua проверяет также ошибки камней, неподдержанные строки предметов и
пользовательских свойств. Причина предупреждения о требованиях не теряется.
Допуск чисел: относительный `1e-10`, абсолютный `1e-9`, с учётом double
и точности JSON Lua. Предупреждения и неподдержанные свойства не подменяются
числовым допуском. Новые причины диагностики требуют отдельной проверки.

`Compare` не изменяет документы и возвращает разницы только для определённых
показателей. При неподдержанном варианте пустой список разниц сопровождается
исходными статусами; отсутствующее значение не становится нулём.

## Расширение 0.0.2

В разработке добавлены Frostbolt Projectile и Spark Base. Общее ядро выбирает
урон и сопротивление противника по стихии, применяет общие и подходящие
стихийные свойства. Тип и режим берутся из проверенного набора; неизвестные
выборы отклоняются. Имена результата Fireball сохранены, новые умения возвращают
соответствующие `Cold*` или `Lightning*` промежуточные показатели.

[Отдельные 84 эталона](../testdata/reference/0.0.2/README.md) проверяются вместе
со старыми 77. Базовые примеры: Frostbolt `TotalDPS=9.1`, Spark
`TotalDPS=8.5642857142857`. При расчёте разных умений параллельно исходные XML
не меняются. CLI/MCP/gRPC проверены отдельными процессами.
Ресурсы восьми базовых классов и требования камней проверены ещё по
[168 случаям](../testdata/reference/0.0.2/classes/README.md); возвышения
не поддерживаются, пассивы других классов ограничены стартом.
[Пять случаев выбора групп/наборов](../testdata/reference/0.0.2/groups/README.md)
подтверждены Lua и процессной проверкой восстановления после Kill.
[Каталог и предпросмотр](CATALOG.md) уже используют общее ядро и ограниченную
очередь; девять случаев предпросмотра проверены по прежним эталонам поддержек.
[Приёмка сессий](SESSION-ACCEPTANCE-0.0.2.md) проверяет три умения, отмену,
события и восстановление. Примеры CLI/MCP — в [руководстве](EXAMPLES-0.0.2.md).

Библиотека проверена параллельными вызовами. Предварительный замер `0.0.1` Windows x64,
Go 1.27.4, Ryzen 9 3900XT: около 214 мкс и 104 КБ выделений на один расчёт
минимальной фикстуры; параллельный режим — около 100 мкс на операцию по общей
пропускной способности. Это не задержка отдельного параллельного запроса,
не пиковая память процесса и не сравнение скорости с Lua. Полная приёмка
сервиса, хранения и опубликованных бинарников выполняется перед выпуском.

Linux CI дополнительно зафиксировал три последовательных и три параллельных
замера с исходным выводом и составом среды: [отчёт производительности](../testdata/performance/README.md).
Медианы — около 135 мкс последовательно и 65 мкс на операцию по общей
параллельной пропускной способности; границы измерения указаны в отчёте.
## Оригинальный расчёт PoB и сравнение задержки

PoB2Engine по умолчанию передаёт XML сборки отдельному процессу LuaJIT и
получает числовые показатели и предупреждения оригинального PoB. Прежний
расчёт сохраняется для сравнений через `POB2_ENGINE_CALCULATOR=go`.

Медиана трёх серий прогретого расчёта на Windows x64, Ryzen 9 3900XT,
PoB v0.23.1. Замер включает сериализацию и передачу запроса к Lua-воркеру.

| Сборка | DPS | Go, мс | Lua, мс |
| --- | ---: | ---: | ---: |
| Fireball | 8,916667 | 0,247 | 169 |
| Frostbolt | 9,100000 | 0,238 | 223 |
| Spark | 8,564286 | 0,226 | 185 |

Первый локальный расчёт Fireball с диска занял около 2,06 секунды по Lua и
0,037 секунды по Go. Время загрузки пакета PoB не входило в замер.
Для повторения укажите абсолютный путь к подготовленному PoB v0.23.1 в
`POB2_ENGINE_POB_DIR` и выполните:

```shell
go test ./internal/pob -run TestLua -bench BenchmarkCalculators -benchtime=400ms -count=3
```

При явном выборе каталога через `POB2_ENGINE_POB_DIR` результаты имеют
`data_id: "pob-lua-local"` и пустые `data_sha256` и `pob_commit`. Для
управляемой установки движок записывает SHA-256 архива и ревизию PoB.

### Эксперимент с WebAssembly

GopherLua v1.1.1 собран как нативная программа, гостевой модуль `js/wasm`
для Node.js 24.22.3 и модуль `wasip1` для wazero v1.12.0. Во всех вариантах
использованы исходные Lua-файлы и данные PoB v0.23.1
(`7d6f530cbdab20389ff8bc6ba97a37ac27f74e41`). Стенд передаёт одинаковые XML
через JSON Lines и сверяет выбранное умение, DPS и отсутствие предупреждений.

Адаптер эксперимента предоставляет `jit.opt`, операции `bit`, используемые
методы `sha2` и тестовую реализацию `lua-utf8` для ASCII. Он читает длинные
входные строки целиком, отключает сохранение временной сборки и настраивает
таблицы GopherLua для разреженных идентификаторов PoB. В варианте wazero
каталог PoB смонтирован только для чтения.

На Windows x64 LuaJIT, нативный GopherLua и GopherLua в Node/V8 дали
одинаковый DPS для трёх сборок. Ниже медиана пяти повторов после первого
расчёта каждой сборки. LuaJIT и нативный GopherLua запускались отдельными
процессами. Стенд запускал Node/V8 и параллельно исследовал wazero,
поэтому время запуска Wasm включает конкуренцию этих процессов.

| Сборка | DPS | LuaJIT, с | GopherLua без Wasm, с | GopherLua в Wasm через Node/V8, с |
| --- | ---: | ---: | ---: | ---: |
| Fireball | 8,916667 | 0,178 | 1,321 | 6,221 |
| Frostbolt | 9,100000 | 0,179 | 1,308 | 6,204 |
| Spark | 8,564286 | 0,180 | 1,375 | 5,907 |

Готовность к первому запросу наступила через 1,72 с для LuaJIT, 28,11 с
для нативного GopherLua и 3 мин 30 с для Wasm в Node/V8. Скачивание PoB
время не учитывает. В обоих успешных прогонах GopherLua порог плотного
массива был 4096.

Первый запуск через wazero истёк по лимиту 8 минут. При монтировании снимка
файлов в памяти и при снижении порога плотного массива гостевой модуль
загрузил дерево, затем завершился с `out of bounds memory access` при росте
памяти гостя. Node/V8 с WASI вернул `EINVAL` при открытии Lua-файла на Windows.
Успешный запуск Node/V8 использовал `js/wasm` и файловую систему Node.js.
