# Понятный код и когнитивная сложность

Код должен читаться как последовательность понятных действий. Название
объясняет назначение функции, параметры явно передают нужные данные,
проверки ошибок завершаются ранним возвратом. Один уровень вложенности
и одна задача на функцию — предпочтительный вариант.

Отдельная функция полезна, когда её имя объясняет законченный шаг:
проверить команду, прочитать узлы, выбрать набор, очистить старый результат.
Избегайте скрытых побочных эффектов, сокращений без понятного контекста,
длинных условий и универсальных конструкций для простых операций.
Формулы и проверки должны оставаться видимыми и объяснимыми.

## Проверка

Для новых и изменяемых функций ориентир — COG не выше 10. После упрощения
нужны прежние тесты и эталоны. Число сложности дополняет чтение кода;
у каждого выделенного шага должно быть самостоятельное понятное назначение.

Используется [treesitter_cyclomatic_complexity](https://github.com/Hecatoncheir/treesitter_cyclomatic_complexity)
с метрикой `cognitive` и стандартным режимом `nested_functions = 'inline'`.
В Neovim с подключённым плагином и анализатором языка:

```vim
:lua require('cyclomatic').setup({metric = 'cognitive', nested_functions = 'inline'})
:Cyclomatic list
:Cyclomatic explain
:Cyclomatic project .
```

Инструмент разработки не является зависимостью движка. Для обычной сборки
Go он не нужен. Установку или обновление сторонних инструментов согласовывайте
отдельно; имеющийся плагин можно использовать без изменения настроек редактора.

В отчёте закреплены версия плагина, Neovim, суммы анализаторов и режим подсчёта.

| --- | --- | --- |
| Применение правки `Edited` | 15 | 8 |
| Выбор наборов `editSelection` | 24 | 7 |
| Обход расширений XML `inspectExtensions` | 22 | 1 |
| Проверка значений XML `inspectSpecialValues` | 21 | 5 |

Чтение и изменение этих участков проверяются вместе с расчётами, сохранением
сессий и событиями. Следующие этапы проходят такую же проверку по мере изменений.
