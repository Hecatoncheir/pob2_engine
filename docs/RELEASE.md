# Проверка и установка выпуска

## Состав

Выпуски по тегам `v*` содержат ZIP для Windows x64, Linux x64 и macOS arm64.
Внутри — `pob2-engine[.exe]`, документация, пример XML, оригинальные лицензии,
происхождение формул и встроенных данных, `COMMIT.txt` и `PACKAGE.json` с
SHA-256 каждого файла. Для расчёта достаточно исполняемого файла: данные встроены.
Архивы исходников и отдельный комплект лицензий публикуются рядом.

Скачайте подходящий ZIP и `SHA256SUMS` со страницы версии. Сравните сумму
архива с указанной: `Get-FileHash ARCHIVE.zip -Algorithm SHA256` в PowerShell
либо `sha256sum ARCHIVE.zip` в Linux. На macOS: `shasum -a 256 ARCHIVE.zip`.
Распакуйте архив в отдельный каталог. На Linux/macOS при необходимости
разрешите запуск через `chmod +x pob2-engine`.

```shell
./pob2-engine --version
./pob2-engine calculate --file testdata/reference/fireball.xml
```

В Windows используйте `./pob2-engine.exe`. Пример возвращает `complete` и
`TotalDPS = 8.9166666666667` с установленным числовым допуском.
Команды сессий, MCP, статусы и резервные копии: [CLI-BUILDS.md](CLI-BUILDS.md).
Проверяйте `status` и `issues`; покрытие ограничено [Fireball](COVERAGE-0.0.1.md).

## Условия публикации

Обычный CI выполняет все тесты только на Linux, включая `-race`, генерацию
контракта и сравнение с закреплённым Lua. Отчёт `calculation-performance-linux`
содержит результаты трёх замеров, Go и процессор; это не сравнение скорости с Lua.

Только релизный тег запускает кросссборки на Linux с `CGO_ENABLED=0`.
Затем Windows, Linux и macOS запускают каждый свой готовый архив.
Проверяются SHA-256 состава, версия, расчёт с пустым PATH, общая сессия CLI/MCP
через gRPC, сравнение без правки, экспорт, резервная копия и восстановление
исходного результата `request_id`. Python нужен проверяющему сценарию, не движку.
Отчёты `smoke_*.json` публикуются с выпуском. Публикация разрешена только после
успеха всех проверок; одних кросссборок недостаточно.

Для кандидата создайте запись `0.0.1-rc.N` в CHANGELOG и тег `v0.0.1-rc.N`.
После успешной приёмки подготовьте запись итоговой версии и тег `v0.0.1`.
Commit тега обязан входить в `main`; существующие выпуски не перезаписываются.
После публикации повторно скачайте архивы, сверьте общий `SHA256SUMS` и
запустите `python tool/smoke_release.py --archive ARCHIVE.zip --tag TAG --report report.json`
на соответствующей ОС. Итоговую проверку запишите в отчёт выпуска.
