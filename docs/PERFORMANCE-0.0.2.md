## Что измеряется

| Участок | Вход | Включено во время |
| --- | --- | --- |
| Библиотека Calculate | Минимальные Fireball, Frostbolt, Spark | Модель, хеширование, проверка входов и расчёт одного умения |
| Сервис PreviewSupport | Отдельная сессия каждого умения, одна активная группа | Снимок и ревизия, общая очередь без конкуренции, разбор/копия XML, добавление поддержки, расчёты до/после и дельты |

Для каждого умения отдельно проверяются Rapid Casting I и Controlled Destruction
уровня 1/качества 0. До предпросмотра в группе только активный камень уровня 1,
без поддержек. После серии снимок должен остаться прежним. Все измеряемые
ответы проверяются на `complete`; предпросмотр — также на `compatible`.

Три минимальных XML совпадают с [примерами](EXAMPLES-0.0.2.md). Используются
Sorceress, старт класса, пустая экипировка и явно выключенные награды заданий.
Ожидаемый исходный TotalDPS: 8.9166666666667 / 9.1 / 8.5642857142857.
Набор: `pob2-0.0.2-spell-hits-v1`, схема 2, дерево `0_5`.

Подготовка движка/сессии, загрузка набора и чтение файла происходят до `b.Loop`.
Проверка неизменности сессии выполняется после остановки таймера. Во время
включена проверка успешного статуса. Кэш сохранённого расчёта не используется:
Calculate и PreviewSupport выполняют вычисления при каждом вызове.

## Воспроизведение

```shell
go test ./internal/calculation -run '^$' -bench '^BenchmarkCalculateSpells$' -benchmem -benchtime=500ms -count=5
go test ./internal/application -run '^$' -bench '^BenchmarkPreviewSupport$' -benchmem -benchtime=500ms -count=5
```

Go калибрует число операций; 500 мс — целевое время одного повторения,
а не фиксированное время запроса. Каждая строка `ns/op` — среднее по операциям
одного повторения. Итоговая таблица содержит медиану пяти таких средних
и диапазон между ними; это не p50/p95 задержек отдельных запросов.

CI сохраняет исходные `spells.txt`, `support-preview.txt`, Go/OS/CPU/kernel,
переменные GOMAXPROCS/GOGC/GOMEMLIMIT (без остальных переменных окружения),
commit, время UTC и SHA-256 XML/встроенных данных. Отдельно остаётся прежний
замер последовательного/параллельного Fireball в `benchmark.txt` (три повторения).
Исходники измерений: [библиотека](../internal/calculation/benchmark_test.go),
[сервис](../internal/application/benchmark_test.go), [CI](../.github/workflows/ci.yml).

## Границы результата

Замеры последовательные, без `-race`, на подготовленном процессе, без ожидания
занятой очереди. PreviewSupport использует сервис в памяти, без журнала.
CLI/MCP/gRPC, запуск процесса, холодная загрузка, bbolt/Sync, несколько клиентов
и тяжёлые сборки сюда не входят. Это не замер общей задержки пользовательского запроса.

`B/op` и `allocs/op` — выделения Go на операцию, а не пиковая память процесса
или объём его живых объектов. GitHub VM и фоновая нагрузка влияют на время;
сопоставление разных машин не доказывает ускорение или регрессию. Порог
производительности для этого выпуска не установлен.

Скорость Lua по тем же условиям отдельно не измерялась; сравнение с ней
не заявляется. [Измерения 0.0.1](../testdata/performance/README.md) сохраняются
как исторический результат своей среды и исходного коммита.
